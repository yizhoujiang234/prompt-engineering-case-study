# 架构总览：一份生产级系统提示词的解剖

> 本文行号均指 `original/Claude-Fable-5.1.md`（2195 行），与各模块头注释一致。

## 1. 文档定位

`Claude-Fable-5.1.md` 是一份部署于消费级产品（Web/App 聊天界面）的**完整系统提示词**，
服务于一个具备以下能力的通用 AI 助手：

| 能力 | 支撑模块 |
|---|---|
| 跨会话持久记忆（文件式记忆系统） | 06、14（memory_* 工具）、15（运行时注入） |
| 工具调用（搜索、展示卡片、文件、bash、位置、天气等 46 个工具） | 14 + 各行为模块 |
| MCP 连接器与插件/技能生态 | 09、18 |
| Artifact 生成，且 Artifact 内可再调 Anthropic API（"Claude in Claude"） | 08、16 |
| 历史会话检索 | 10、14 |
| 图片搜索与引用合规 | 12、13、17 |

## 3. 五层架构

```
                ┌─────────────────────────────────────────────┐
                │  L5 运行时层（每会话动态拼装，非手写）           │
                │  15 profile/memory_listing 占位 · 当前日期     │
                │  （L1812 声明"在对话中提供"）· 用户位置（L2043） │
                │  18 技能清单 · 19 网络与文件系统配置             │
                └──────────────────────┬──────────────────────┘
                                       │ 每次会话注入
   用户消息 ─────────────────────────► ▼ ──► 模型
                ┌─────────────────────────────────────────────┐
                │  静态系统提示词（产品团队维护，即 modules/ 01–14、16、17）│
                │                                             │
                │  L1 身份层   01 身份与产品信息                  │
                │  L2 安全层   02 拒答 · 07 会话结束 · 12 版权    │
                │  L3 行为层   03 语气 · 04 心理关怀 · 05 价值观  │
                │  L4 能力层   06 记忆 · 08 Artifact · 09 MCP    │
                │             10 历史会话 · 11 计算机使用         │
                │             12 搜索 · 13 图片 · 14 工具         │
                │             16 Artifact API · 17 引用          │
                └─────────────────────────────────────────────┘
```

各层职责：

- **L1 身份层**：模型是谁（Claude Fable 5.1，Claude 5 家族中高于 Opus 的 Mythos 级）、
  产品矩阵（API、Claude Code、Cowork、Chrome/Excel/PPT 集成、Slack 中的 Claude Tag）、知识截止（2026 年 6 月底）；
- **L2 安全层**：儿童安全（critical 块）、危险内容拒答、版权角色绘制边界、会话结束工具的安全例外、
  搜索与版权硬限制、有害内容过滤、引用合规；
- **L3 行为层**：语气与格式、列表使用纪律、工具调用后必须实质回复、心理关怀边界、政治中立、认错方式；
- **L4 能力层**：记忆文件系统、Artifact 存储、MCP 生态、历史会话检索、文件产出路由、
  搜索行为、图片搜索、工具定义、Artifact 内 API、引用格式；
- **L5 运行时层**：占位符与环境配置，每次会话由系统拼装，产品团队不直接维护其内容。

> 跨层说明：12 号模块同时横跨 L2 与 L4——版权硬限制属安全层，搜索触发与有害内容过滤属能力层；
> 上文 L2 归属取的是其中最高优先级的部分。07（会话结束）也兼具安全与能力两重属性。

## 4. 静态指令 vs 运行时注入（关键洞察）

系统提示词不是一份"写死的文档"，而是**模板**：

| 类型 | 内容 | 证据 |
|---|---|---|
| 纯静态 | 01–14、16、17 号模块 | 手工撰写、版本化维护 |
| 运行时占位 | `<profile>(not yet written)</profile>`、`<memory_listing>` | L1817–1823 |
| 对话中注入 | 当前日期 | L1812 明确声明"在下方对话中提供" |
| 环境生成 | 技能清单、网络白名单、只读挂载 | 18、19 号模块，随部署变化 |
| 脱敏痕迹 | `{LOCATION_REDACTED}`、"One listing entry withheld — user data, not prompt text" | L2043、L1822 |

这说明该提示词的拼装管线是：**静态正文 + 用户档案/记忆清单 + 日期/位置 + 环境配置**，
每个会话的完整系统提示词内容都不同。

## 5. 篇幅分布洞察

| 模块 | 占比 | 说明 |
|---|---|---|
| 06 记忆系统 | **38.2%** | 最大单项，含 17 个示例、6 个分组 |
| 12 搜索与版权 | **10.8%** | 版权硬限制 + 8 个示例 |
| 11 计算机使用 | **9.7%** | 文件路由 + Artifact 判定 + 视觉路由 |
| 16 Artifact 内 API | **9.2%** | "Claude in Claude" 应用开发指南 |
| 其余 15 个模块 | ~31% | 均为 2% 以下的小模块 |

**结论**：约 68% 的篇幅花在"个性化（记忆）"与"能力路由"上；
基础安全（02+04+07+12 中有害内容部分）合计约 5–6%——规则密度极高但篇幅克制。
这份提示词的工程重心不是"防止出错"，而是"让 46 个工具、11 个技能、
MCP 连接器在正确时机被正确使用"。

## 6. 正文与工具定义的分工

- **正文（行为模块）负责"何时用"**：何时搜索、何时出文件、何时出卡片；
- **工具 description 负责"何时不该用 + 细节路由"**：
  例如 xlsx 工具描述写满触发词与排除项；product-self-knowledge 技能描述里
  直接写"你的训练数据可能过时或错误，请来这里核实"。

修改工具行为时，**优先检查 14 号模块的工具 description**，而不是正文。

## 7. 写作风格观察

1. 全文第二人称指令（"Claude should…"），无系统侧说教；
2. 高危规则用 `<critical_*>` 或全大写标签包裹（如 `<CRITICAL_COPYRIGHT_COMPLIANCE>`）；
3. 每条硬规则附近必配示例或反例（见 docs/02 模式 2）；
4. 大量使用"判断测试"句式替代枚举（见 docs/02 模式 3）；
5. 模块间用空行分隔但不用编号——分层靠标签命名与顺序隐式表达。
