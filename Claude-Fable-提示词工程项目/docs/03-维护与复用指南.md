# 维护与复用指南

> 面向要基于本项目做修改、裁剪或移植的人。行号均指 `original/Claude-Fable-5.1.md`。

## 1. 安全的修改流程（黄金法则）

```
编辑 modules/ 中的单个模块
  → 运行 scripts\rebuild.ps1
  → 看到 PASS（与基准逐字节一致或仅有预期差异）
  → 若改动导致行数/边界变化：同步更新 scripts\split.ps1 的模块定义表，重跑 split
  → 运行 scripts\check-refs.ps1（确认文档中的 L 行号引用没有失效）
  → 语义评审（用 templates\提示词评审清单.md）
  → 改动涉及行为规则时：跑 evals\ 自动用例（scripts\run-evals.ps1）
```

铁律：

1. **永远不要直接编辑 `original/`**——它是基准副本，diff 的参照系；
2. **一次只改一个模块**，改完立即 rebuild 校验，再改下一个；
3. 模块边界（行号）变化必须先改 `split.ps1` 的模块表，否则切分与重组会失配；
4. 改动若触及示例，遵循原格式（`<example>` + good/bad + rationale）。

## 3. 冲突优先级（改动前先回答"它排第几"）

原文隐含的优先序，冲突时靠它裁决：

1. 儿童安全（critical 块）
2. 版权与法律合规
3. 用户心理安全
4. 隐私（never_store 清单）
5. 用户体验与便利

新增规则先归类层级，并检查是否与更高层级冲突；
**下游模块不得弱化上游 critical 块**（例如为提升体验而放宽版权引用上限）。

## 5. 变体配方

### A. 最小对话助手（~8% 篇幅）
保留：01 + 02 + 03 + 05 + 14（仅必要工具 schema）。
用途：嵌入式客服、轻量问答。删掉一切能力路由与示例。
组装：`scripts\rebuild.ps1 -Include '01,02,03,05,14'` → rebuilt-variant.md（227 行）。

### B. 编程助手（~20%）
保留：01 + 02 + 03 + 05 + 11 + 14 + 19。
改造点：11 号模块的文件路由从"文档产出"改写为"代码仓库场景"；
19 号白名单按公司内部源调整。
组装：`scripts\rebuild.ps1 -Include '01,02,03,05,11,14,19'`，再手工改造 11/19。

### C. 个性化记忆助手（~50%）
保留：01–07 + 14（memory_* 六件套）。
要点：06 是**独立可移植单元**——记忆格式规范、隐私三层模型、
17 个示例可以原样搬走，只需替换工具 schema 的命名空间。
组装：`scripts\rebuild.ps1 -Include '01,02,03,04,05,06,07,14'`。

## 6. 回归测试（已落地为 evals/ 用例库）

原文 60+ 处示例中的 26 条核心用例已结构化为 `evals\cases.jsonl`
（记忆 17 + 版权 3 + 搜索路由 5 + 拒答 1），详见 [evals/README.md](../evals/README.md)：

| 用例集 | 数量 | 判定方式 |
|---|---|---|
| 记忆应用 | 17 | 自动（好/坏回答特征词断言） |
| 版权合规 | 2+1 | 2 自动 + 1 人工（词数/单源次数） |
| 搜索触发 | 5 | 人工/裁判模型（需真实工具观察路由） |
| 拒答 | 1 | 人工（拒绝+原创替代+不变体） |

运行方式：`scripts\run-evals.ps1 -SystemFile rebuilt.md -Base <API> -Model <模型> -Key <KEY>`
（`-DryRun` 只校验用例格式；`-Filter mem` 只跑某一类）。

建议流程：每次改动行为模块后跑一遍对应类别的用例；
正例断言行为出现，反例断言翻车点不出现。改动后先跑基线记分，目标是"不退化"。
