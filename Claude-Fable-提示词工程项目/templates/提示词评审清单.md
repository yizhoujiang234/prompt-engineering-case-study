# 系统提示词评审清单

> 逐项打勾，任何一项不过先修再上线。括号内例证引自本项目 `original/` 原文。

## A. 结构与可读性

- [ ] 分层清晰（身份 / 安全 / 行为 / 能力 / 运行时），单模块职责单一
- [ ] XML 标签 snake_case 命名一致，全部正确闭合
- [ ] 每条硬规则附近有示例或反例
- [ ] 无互相矛盾的指令（重点排查：语气 vs 拒绝、工具优先级 vs 默认行为）
- [ ] 有重组/校验机制，任何改动可 diff（应有独立的基准副本 + 逐字节重组比对，例：`split/rebuild` 脚本对）

## B. 安全覆盖

- [ ] 最高优先级风险有 critical 块，且 ≤5 条（原文：儿童安全）
- [ ] 危险请求的拒绝方式统一（拒绝 + 理由 + 替代方向）
- [ ] 医疗/法律/财务：给信息不给决定，有免责表述
- [ ] 心理危机场景有资源指引，且不使用危险"替代法"建议（原文：禁冰块/橡皮筋）
- [ ] 拒答后提供"不可识别"的原创替代，而不是冷拒绝（原文：版权角色绘制）

## C. 版权与引用

- [ ] 直接引用有数值上限（原文：<15 词）
- [ ] 每来源直接引用次数有上限（原文：≤1 次）
- [ ] 歌词/诗歌/书文长段明确禁止复现（公版年份线之前除外）
- [ ] 基于搜索的回答有引用格式规范，且要求用自己的话转述

## D. 隐私（有记忆/存储功能时必查）

- [ ] 存储规则分三级：默认不存 / 谨慎存 / 绝不存
- [ ] 有"用户明确要求也不执行"的行为护栏（原文：拒绝"只夸不批"类指令）
- [ ] 有禁用表述清单（原文：禁说"根据你的记忆…"）
- [ ] 受保护属性（种族/宗教等）、证件号、未成年身份等在绝不存清单中

## E. 行为一致性

- [ ] 判断测试代替长枚举（至少 3 处；原文："一个月后还成立吗"）
- [ ] 模糊词（适度/尽量/一般来说）已尽量替换为数字或问句
- [ ] 示例组覆盖四类：最小场景 / 典型场景 / **不用场景** / **边界场景**
- [ ] 禁用词表存在且可追加（原文：genuinely / honestly）

## F. 工具与路由

- [ ] 多工具竞争场景有显式决策顺序 + 兜底出口
- [ ] 每个工具 description 含三要素：何时用 / 何时不用 / 与相近工具的优先级
- [ ] 门槛操作（付费/外发/删除）先建议后执行
- [ ] 工具调用后必须实质回复的规则存在

## G. 可维护性

- [ ] 易变内容（日期/档案/清单/环境）为运行时占位，非硬编码
- [ ] Token 预算有账：top 3 模块占比清楚，裁剪顺序已定义
- [ ] 修改流程成文：改哪里 → 怎么校验 → 谁复核

## H. 上线前

- [ ] 用提示词自带示例构造了回归用例（正例断言行为出现，反例断言不翻车）
- [ ] 安全与隐私段落经过安全/法务复核
- [ ] 在目标模型上跑过基线 eval，记录得分供后续版本对比
